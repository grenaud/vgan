# vgan v4.0.1 "melanzana"

A patch release of v4.0.0. It changes how TrailMix handles temporary files, adds `--keep-gam`, and documents a HaploCart/euka/soibean crash that affects every second run (with its workaround). Install and database instructions are in the [README](https://github.com/grenaud/vgan#installation); the full notes of the previous release are in [v4.0.0](https://github.com/grenaud/vgan/releases/tag/v4.0.0).

To upgrade from v4.0.0, replace the binary. Nothing else changes: the database files, the SAFARI mapper and `none.prof` stay as they are.

## Changes since v4.0.0

### TrailMix

* **The `-z` (temporary directory) option is gone.** Temporary files (the mapped reads as a GAM, RPVG's raw output, the cleaned damage profiles) are written to `<output prefix>tmp_XXXXXXX/` next to the results, and the folder is **removed when the run finishes**. Before, the `-z` folders were never cleaned up and piled up. A run that fails keeps its folder, for debugging. `-z` is still accepted but ignored, with a warning, so existing command lines keep working.
* **The folder that `-o` points into is created if it does not exist.**
* **New: `--keep-gam`.** Keeps the mapped reads as `<prefix>reads.gam` (they are deleted by default). The file is about as large as the mapped reads.
* `vgan version` prints `v4.0.1`.

### Documentation

* README: how to check a database download, which files need write permission, the installation of the static binary (where vgan looks for its files, the SAFARI mapper, `none.prof`), common build problems, and the TrailMix quick start with test data and an interpretation of the result.
* The R-hat values of the quick start vary between runs (one run had 1.056 for the position of the Neanderthal source and printed a warning); the README says what to do.

## Known issues (please read)

* **HaploCart, euka and soibean crash when the giraffe cache files already exist.** On the first run vg builds `*.shortread.withzip.min` and `*.shortread.zipcodes` next to the database. A later run that finds them fails (HaploCart: `Caught signal 6` or `11`, or it hangs). We saw it with the static binary, a dynamic build and the database on our server. It is a bug in the vg giraffe version vgan uses, not in the release binary. **Workaround: delete the two cache files before every run** (they are rebuilt in about 15 seconds):
  ```
  rm -f $HOME/share/vgan/hcfiles/*.shortread.withzip.min $HOME/share/vgan/hcfiles/*.shortread.zipcodes
  ```
  Use the folder of the database you run (`euka_dir`, `soibean_dir`, or the one given to `--hc-files`). We tested the workaround for HaploCart (`-f rCRS.fa`: haplogroup H2a2a1 in 20 seconds); euka and soibean build the same files and are very likely affected. TrailMix is not affected (it maps with SAFARI).
* **TrailMix with GAM input (`-g`) hangs** while reading the file; use FASTQ input.
* TrailMix needs the separate SAFARI binary (790 MB), `none.prof` must exist even if you give your own damage profiles, and TrailMix and euka need write permission on the `.dist` index of the database (see the README).
* The other known limits of v4.0.0 apply: soibean's damage-model changes are not validated on a soibean data set, tempeh needs a separate build of cdx, Linux x86_64 only.
