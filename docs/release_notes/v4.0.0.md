# vgan v4.0.0 "melanzana"

**TrailMix** (deconvolution and phylogenetic placement of hominin sedaDNA mixtures) joins HaploCart, euka and soibean, and all subcommands now run on **vg v1.75**. This release also adds a documented from-source build (`build_deps.sh`), a static Linux binary, new database archives on Google Drive, and a README that replaces the GitHub wiki.

## Install in five minutes

```
mkdir -p $HOME/bin $HOME/share/vgan/{euka_dir,hcfiles,soibean_dir,tmfiles,damageProfiles,plottingScripts} $HOME/dep/safari_vg/bin
curl -L -o $HOME/bin/vgan https://github.com/grenaud/vgan/releases/download/v4.0.0/vgan-linux-x86_64
chmod +x $HOME/bin/vgan
export PATH=$HOME/bin:$PATH
wget -O $HOME/share/vgan/damageProfiles/none.prof https://raw.githubusercontent.com/grenaud/vgan/main/share/vgan/damageProfiles/none.prof
vgan version
```

Then download the database of the subcommand you want (README, "Database files"). For TrailMix also download the SAFARI mapper:

```
curl -L -o $HOME/dep/safari_vg/bin/vg https://github.com/grenaud/SAFARI/releases/download/v1.0.1/vg
chmod +x $HOME/dep/safari_vg/bin/vg
```

### Things that are not obvious

* **Where vgan looks for files.** Relative to the real location of the executable: databases in `../share/vgan/`, the SAFARI mapper in `../dep/safari_vg/bin/vg`, the default damage profile in `../share/vgan/damageProfiles/none.prof`. With the binary in `$HOME/bin` these are `$HOME/share/vgan/...` and `$HOME/dep/...`. A symbolic link to the binary is followed to the real file, so the real file has to sit next to the `share` and `dep` folders. The database folders can be moved with `--hc-files`, `--euka_dir`, `--soibean_dir` and `--tm-files`; the SAFARI mapper and `none.prof` cannot be moved.
* **`none.prof` must exist** even when you give your own `--deam5p`/`--deam3p`; otherwise vgan stops with `getFullPath failed on .../damageProfiles/none.prof`.
* **Write permission.** TrailMix (and euka) open the `.dist` index of the database for writing; without it the mapper stops with `Permission denied`. HaploCart, euka and soibean write two cache files (`*.shortread.withzip.min`, `*.shortread.zipcodes`) into the database folder on first use; the folder must be writable, and the first run is slower.
* **Use `curl -L`.** The release link redirects; without `-L` you save a small HTML file.
* **x86_64 Linux only.** Not for macOS or ARM. `file vgan` should say "statically linked". On a file system mounted `noexec` the binary does not start; use another folder.
* **`vgan version` prints to stderr.**
* **Static glibc.** Linking statically against glibc prints warnings about `getpwuid`, `getaddrinfo` and `dlopen` (they are expected). They matter only for user-name lookups through NSS (LDAP, NIS), which vgan uses to expand `~` in file names; give absolute paths on such systems.

## What is new

### TrailMix (new subcommand)

`vgan trailmix` deconvolves a mixture of hominin mitochondrial DNA into *k* sources. For every source it estimates the proportion in the mixture and its placement on a phylogenetic tree of mitochondrial genomes (branch and position along the branch), with an MCMC.

* **Input:** single-end or merged FASTQ (`-fq1`), paired-end (`-fq1 -fq2`), or GAM (`-g`). Damage profiles for the 5' and 3' ends with `--deam5p/--deam3p`.
* **Pipeline:** reads are mapped to the mitochondrial pangenome with SAFARI (a damage-aware giraffe), RPVG finds the haplotypes in the reads to initialize the chain, and the MCMC samples the proportions and placements. Several chains run one after the other (`--chains`), so they can be compared.
* **Likelihood.** The probability of a read base marginalizes over the unobserved base after mutation on the branch (HKY substitution model) and over deamination and sequencing error. Each source can be marked ancient or modern with `--is-ancient`. Mapping quality and mappability do not enter the likelihood of supported bases.
* **Sampler.** Each iteration moves one source by a symmetric random walk on the tree (so there is no Hastings correction), with the step size drawn from a mixture of scales.
* **Outputs** (with `-o PREFIX`, a file name prefix): per-chain `...Result<k>_chain<N>.mcmc.gz` and `...Trace<k>_chain<N>.detail.mcmc.gz`, `...BranchEstimate.txt` and `...BaseProportionEstimates.txt` (estimates, intervals and effective sample sizes), `...Diagnostics.txt` (R-hat), RPVG's haplotype tables, and `...summary.txt` (run settings and the database used, which the plot script reads).
* **Plotting:** `share/vgan/plottingScripts/plot_trailmix_trees.py PREFIX` draws, for every chain and for the best-mixing chain, the tree with the posterior placements on the branches, the proportion densities, the placement posterior, traces and chain agreement, in publication style (PDF, and PNG with `--png`). It also writes a collapsed version of the tree in which lineages that no iteration landed in (Denisovans, Neanderthals, L0 to L6, M, N) become vertical bars. The main tree is never replaced.
* **Databases:** `tmfiles` (default, 12,852 paths) and `publication_tmfiles` (the database of the publication: 64 mitogenomes as tips, 126 paths, rebuilt from scratch, see below). The publication database is used with `--tm-files .../publication_tmfiles/ --dbprefix pub.graph`.
* **Quick start with test data and a worked interpretation:** [README, "TrailMix quick start"](https://github.com/grenaud/vgan#trailmix-quick-start) (782 reads, about 7 minutes).

The `publication_tmfiles` database in this release was **rebuilt from scratch** (MAFFT alignment, IQ-TREE HKY+F tree and ancestral states, PGGB graph, vg indexes) and no longer has the `homo_heidel` path. In the earlier build, `homo_heidel` carried 4,590 bp of private nodes that attracted reads and pulled the chains onto it. The tree topology and the 126 path names are unchanged; **internal node names after `Node45` are the old ones minus one** (`node_name_map_old_to_new.tsv` in the archive maps them). Results from the earlier database cannot be compared name by name.

### tempeh (new subcommand)

`vgan tempeh` builds and inspects a CDX pangenome coordinate index, or computes GAM coverage against one. It runs the separate [cdx](https://github.com/JolanBoucher/cdx) program as a subprocess; **the static binary does not include it**, and `build_deps.sh` does not build it. See `vgan tempeh --help`.

### vg v1.75

* euka, soibean, HaploCart and TrailMix are ported to vg **v1.75.0-258** (commit `6193310e3`; vgan pins this exact commit because it links vg's internals).
* Reference graphs (`*.og`) are read as **HashGraph** files, and the mappers use the combined giraffe index (`.giraffe.gbz`, `.dist`, `.min`). **Databases built for earlier releases do not work; use the new archives.**
* euka and soibean silently dropped short reads: vg hardcodes the short-read minimizer length and window (29 and 11) and replaced the supplied index. vgan now overrides these values.
* Damage profiles may contain `nan` entries (written by some tools where no C/G was observed). They are read as 0 and reported with a `[WARNING]` line. TrailMix hands SAFARI a sanitized copy of the profile, because SAFARI cannot parse `nan`.

### Changes to soibean (read before using it)

The damage model of soibean had the same problems that were found and fixed in TrailMix: the alignment-to-node indexing, the per-base quality and damage positions, and a damage term that did not depend on damage. These fixes are in this release and **have been compiled but not validated on a soibean data set**. soibean results can differ from v3.1.0. Please check them against a known sample before relying on them. Details: `SOIBEAN_DAMAGE_MODEL_NOTES.md`.

### Build, packaging and documentation

* **`build_deps.sh`** builds everything vgan links, in one step: libgab, spimap, rpvg (the vgan fork [grenaud/rpvg](https://github.com/grenaud/rpvg) at the tag `vgan-1`, which is upstream rpvg plus the changes vgan needs, described in `VGAN.md` there), vg at the pinned commit (only `libvg.a` and the objects vgan links, not `bin/vg`), the SAFARI binary, and then vgan. Steps that are done are skipped. It replaces the machine-specific `build_with_vg_newest.sh`.
* **`src/Makefile`** no longer tries to download dependencies from the DTU FTP server, which is no longer available. If a dependency is missing, `make vgan` stops and says to run `build_deps.sh`. The stamp files `src/*made` are no longer tracked in git.
* **Static binary:** `make -C src static` (after `build_deps.sh`) builds a fully static x86_64 binary.
* **README** now holds what was on the GitHub wiki (installation, euka, HaploCart, soibean, the aeDNA workflow, unit tests), plus TrailMix, a rewritten installation chapter (release binary, no-sudo source build, permissions, common problems) and a quick start. The commands from the wiki that failed as written were fixed.
* **Databases** (`euka_dir`, `hcfiles`, `soibean_dir`, `tmfiles`, `publication_tmfiles`) are on Google Drive, with `curl` commands in the README. The Makefile targets `hcfilesmade`, `eukafilesmade` and `soibeanfilesmade` download them.
* `trailmix --help` lists `--deam5p` and `--deam3p`.
* **TrailMix: the `-z` (temporary directory) option is gone.** Temporary files are written to `<output prefix>tmp_XXXXXXX/` next to the results and removed when the run finishes (kept if the run fails, to help debugging). The folder that `-o` points into is created if it does not exist. `-z` is still accepted but ignored (with a warning), so existing command lines keep working.

## Known issues and limits

* **Upstream giraffe cache bug.** vg/bdsg can fail with `SnarlDistanceIndex::get_node_from_sentinel: Assertion 'is_chain(parent_chain)' failed`. It occurs on some longer reads and intermittently in HaploCart's `-f` (consensus FASTA) mode, in static and dynamic builds. Short-read FASTQ input is not affected. It is a vg issue, not one of vgan.
* **TrailMix needs a separate SAFARI binary** (790 MB). The build is the damage-aware giraffe of [SAFARI](https://github.com/grenaud/SAFARI) (vg 1.44 based), run as a subprocess. For `safari` mapping, the `v1.0.1` release binary gave identical alignments to the development build for 33,550 of 33,551 test reads; the one difference is a heavily damaged read at the edge of alignability.
* **Not tested in this release:** TrailMix with paired-end input, GAM input, `--library-type` and `--is-ancient`; euka, soibean and HaploCart with a from-source clean build. `--contamination-mode` is accepted but no longer changes the likelihood (use `--is-ancient`).
* **The rpvg that vgan uses is modified.** `--filt-best-score` and `--path-node-cluster` have no effect, identical read-path rows are no longer merged, and `--vgan-temp-dir` is required but unused. On the one single-end sample compared, it gave the same result as the build of the publication; the paired-end path merging differs from upstream and is untested. Details: `VGAN.md` in the fork.
* **Run-to-run variation.** The MCMC uses random numbers, so repeated runs differ in the second digit. Compare chains (R-hat, effective sample size) before trusting an estimate; the quick start shows what to look at. The effective sample sizes of the placement positions are small with the 20,000 iterations of the quick start; use more (for example `--chains 5 --iter 100000`).
* **Platform:** Linux x86_64 only. From-source builds were tested on Ubuntu 24.04 (g++ 13.3) and with g++ 15.2.

## Upgrading from v3.x

1. Download the new database archives; the old graph files are not read.
2. For TrailMix, install the SAFARI mapper and `none.prof` (see above).
3. Re-run soibean results that matter with the new version and check them.
4. If you build from source, use `build_deps.sh`; plain `cd src && make` no longer fetches anything.
